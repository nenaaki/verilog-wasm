# verilog-wasm

Verilog サブセット（ゲート + レジスタ）を **WebAssembly バイナリに直接コンパイル**して、ブラウザ / Node で実行する。

外部ツールチェーンは使わない。LLVM も Binaryen も wat2wasm も不要で、WASM バイナリを JS で組み立てて `WebAssembly.instantiate` に渡している。依存パッケージはゼロ。

```bash
node test/run.js                                     # テスト
node test/ui.js                                      # 回路エディタの操作テスト (Chrome が必要)
node tools/vwc.js examples/lfsr8.v --run 8 --set q=1 # 波形を出す
node tools/vwc.js examples/lfsr8.v --wat             # 生成コードを見る
node tools/bench.js                                  # スループット計測
node tools/serve.js                                  # → http://localhost:8080/web/ （テキスト版 / 回路エディタ）
node tools/vwc.js examples/lfsr8.v -o lfsr8.wasm     # .wasm を書き出す
```

生成した WASM はブラウザ側からも保存できる。テキスト版は「出力」の `.wasm を保存` / `.wat を保存`、回路エディタは「回路」の `.wasm を保存` で、いまコンパイルできているモジュールがそのまま落ちてくる（`WebAssembly.compile` に渡せる素のバイナリなので、他のホストからも読める）。

```text
$ node tools/vwc.js examples/shift8.v --run 8 --set din=1
shift8: nets=12 gates=0(+2 刈り取り) regs=8 state=144B wasm=332B
 cyc | din |        q
-----+-----+---------
   0 |   1 | 00000000
   1 |   1 | 10000000
   2 |   1 | 11000000
   3 |   1 | 11100000
   ...
```

## 対応している Verilog

```verilog
module reg_en(
  input clk,
  input en,
  input [3:0] d,
  output reg [3:0] q
);
  always @(posedge clk)
    q <= en ? d : q;      // ?: はマルチプレクサになる
endmodule
```

- `module` / `endmodule`、ANSI・非 ANSI 両方のポートリスト
- `input` / `output` / `wire` / `reg`、`[msb:lsb]` のベクタ
- `assign` による組合せ代入
- ゲートプリミティブ `and` `or` `not` `nand` `nor` `xor` `xnor` `buf`（多入力可）
- 式：ビット演算 `~` `&` `^` `|` `~^`、リダクション `&a` `|a` `^a` `~&a` `~|a` `~^a`、論理演算 `!` `&&` `||`、算術 `+` `-`（単項 `-` も）、比較 `==` `!=` `<` `<=` `>` `>=`（符号なし）、シフト `<<` `>>`、`? :`、ビット選択 `a[3]`、部分選択 `a[7:4]`、連接 `{a, b}`、`8'hFF` / `4'b1010` / `10` などのリテラル
- `always @(posedge clk)` + `<=`（ノンブロッキング代入）→ D フリップフロップ
- `always` の中の `if` / `else` / `else if`、`case` / `default`（`begin` / `end` で入れ子可）
- 非同期リセット `always @(posedge clk or posedge rst)`（`negedge rst_n` + `if (!rst_n)` の負論理も）
- モジュール階層（インスタンス化とポート接続。順番指定・名前指定の両方）
- `parameter` / `localparam` とパラメータ付きインスタンス化（`#(.WIDTH(4))`）、`[WIDTH-1:0]` のような定数式の範囲

**未対応**：乗除算、`casez` / `casex`、`generate`、`initial`、`function` / `task`、複数クロック、負エッジのクロック、`x` / `z`（`===` / `!==` も）、signed（`<<<` / `>>>` も）。いずれも行番号付きのエラーになる。

`<=` はノンブロッキング代入と「以下」を兼ねる。`always` 文の代入は左辺を読んでから `<=` を食べるので、式の中に出てきた `<=` だけが比較になる（Verilog 本来の解き方と同じ）。つまり `q <= a <= b;` は「`a <= b` の結果を `q` に代入」と読める。

GUI 側にも別の平坦化がある — 回路エディタの「回路部品」は中身を親に取り込んで 1 個の平坦な module にするので、Verilog を経由する時点では階層が解けている（[回路部品](#回路部品)）。

### 幅の規則

Verilog の**文脈依存幅**をそのまま実装している。式の幅は 2 段階で決まる:

1. 下から**自己決定幅**を求める
2. 上から**文脈幅**を配り、文脈依存の演算子は `max(自己決定幅, 文脈幅)` で計算する

自己決定幅:

| 式 | 自己決定幅 |
| --- | --- |
| サイズ付きリテラル | その幅 |
| サイズ無しリテラル | 32 ビット（Verilog の `integer` と同じ → [下記](#サイズ無しリテラルの幅)） |
| 信号・ビット選択・部分選択 | 宣言どおり |
| `~` `-`（単項） | オペランドの幅 |
| `&` `\|` `^` `+` `-` | `max(両辺)` |
| `? :` | `max(値側の 2 つ)` |
| `<<` `>>` | 左オペランドの幅 |
| 連接 `{}` | パートの合計 |
| 比較・`!` `&&` `\|\|` | 1 |

文脈を**受け取る**のは `~` `&` `|` `^` `+` `-`（単項も）、`?:` の値側、`<<` `>>` の左オペランド。
**受け取らない**のは比較・論理演算（結果が 1 ビットに決まっている）、連接のパート、シフト量、`?:` の条件、ビット選択。

代入は左辺の幅を文脈として右辺に配り、最後に左辺の幅へ切り詰め / ゼロ拡張する。だから同じ式が代入先で変わる:

```verilog
wire [3:0]  a = 3, b = 5;
wire [3:0]  w4  = a - b;   // 14
wire [4:0]  w5  = a - b;   // 30
wire [7:0]  w8  = a - b;   // 254
wire [15:0] w16 = a - b;   // 65534
```

加算の桁上げも同じ仕組みで受ける。`wire [3:0] s = a + b;` は 4 ビットで計算して桁上げを捨て、`wire [4:0] s = a + b;` なら残る。「桁上げが欲しければ代入先を 1 ビット広くする」という形になる。

文脈が配られない位置では、部分式が自分の幅で計算される:

```verilog
wire [7:0] x1 = {4'h0, a - b};     // 14。連接のパートは自己決定
wire [7:0] x2 = (a - b) == 8'hFE;  // 1。比較は外の文脈を受け取らないが、両辺は互いの max に揃う
wire [7:0] x3 = (a - b) == 4'hE;   // 1。こちらは両辺 4 ビットで揃う
wire [7:0] x4 = (a << 4) && 1'b1;  // 0。論理演算のオペランドは自己決定なので 4 ビットで押し出される
```

比較の両辺が互いの `max(幅)` に揃うのは Verilog の規則そのままで、「外の文脈は受け取らないが、オペランド 2 つで文脈を作る」と読める。`case` 式とそのラベルも同じように、全部の `max(幅)` に揃う。

**幅の扱いは Verilog と一致している。** signed を扱わないので符号拡張の分岐が無く、すべて符号なし（ゼロ拡張）になる点だけが単純化されている。

#### サイズ無しリテラルの幅

サイズを書かないリテラル（`10` や `'hFF`）は Verilog の `integer` と同じ **32 ビット**として扱う。値が収まる最小幅にすると、文脈幅が配られない位置で `1 + 1` が 1 ビットの `0` になってしまい Verilog と食い違う。

```verilog
wire [7:0] y1 = a << (1 + 1);        // a << 2。1 + 1 は 32 ビットで計算されるので 2
wire [7:0] y2 = a << (15 + 1);       // 0。15 + 1 は折り返さず 16 になり、全部押し出される
wire       y3 = a + 1 <= b;          // 両辺が 32 ビットに揃うので a + 1 も折り返さない
```

**32 ビットにしても回路は大きくならない。** [定数畳み込み](#定数畳み込みと共通部分式除去)が定数側をたたみ、残った上位ビットは[刈り取り](#到達不能ゲートの刈り取り)で消えるので、サイズを書いた場合と同じ回路になる:

```verilog
q <= q + 1;             // q <= q + 8'd1 とゲート数・WASM バイト数まで一致
assign y = p >> (8 - amt);   // p >> (4'd8 - amt) と完全に一致 (48 ゲート)
```

後者は畳み込みが無いと 259 ゲートになる（シフト量はバレルシフタが全ビットを見るので刈り取りが効かない位置）。

### リダクション演算子

全ビットを 1 個のゲート列に畳んで 1 ビットにする。前置に書く:

| 式 | 意味 |
| --- | --- |
| `&d` | 全ビットの AND（全部 1 か） |
| `\|d` | 全ビットの OR（どれか 1 か） |
| `^d` | 全ビットの XOR（1 の個数が奇数か = パリティ） |
| `~&d` `~\|d` `~^d` | それぞれの反転（NAND / NOR / XNOR） |

`&` `\|` `^` は中置にも出てくる記号だが、**オペランドが来る位置に現れたら必ずリダクション**なので曖昧にならない。`~&d` は `~` と `&` に割れても「1 ビットの結果を反転」になるので、専用トークンは要らない。

#### `^~` だけ 1 トークンにしている

`~^` と `^~` は 1 トークンとして扱う。`^` と `~` に割れると `^~d` が「`~d` のリダクション XOR」になり、**幅が偶数のとき Verilog の XNOR リダクションと合わない**（`^(~d)` は `(^d) ^ (幅 mod 2)`）。

```verilog
wire [3:0] d = 4'b0001;
wire x = ~^d;      // 0。XNOR リダクション
wire y = ^(~d);    // 1。~d = 4'b1110 のパリティ。幅が偶数なので別物
```

1 トークンにすると `a ^ ~b` が `a ^~ b` に食われるが、**中置の `^~` をビットごとの XNOR として実装してあるので値は同じ**になる（Verilog も同じ理由で困らない）。

オペランドは自己決定幅で、結果は 1 ビット。`{^d, d}` のように連接の中でも使える。n ビットのリダクションはゲート n-1 個で、[examples/parity8.v](examples/parity8.v) の 8 ビットパリティは xor 7 個。

### ビット演算子と論理演算子

紛らわしいので並べておく。`!` は「全ビットが 0 か」を見て 1 ビットを返し、`~` はビットごとに反転する:

```verilog
wire [3:0] a = 4'b0010;
wire [3:0] x = ~a;             // 4'b1101。ビットごと
wire       y = !a;             // 0。a は 0 ではないので偽
wire       z = a && 4'b0100;   // 1。どちらも 0 ではない
wire [3:0] w = a &  4'b0100;   // 4'b0000。ビットごとの積
```

短絡評価は無い（ハードウェアなので両辺とも常に評価される）。式に副作用が無いので、観測できる違いにはならない。

### if / case の落とし方

`if` / `case` は `always @(posedge clk)` の中だけで使える。組合せ用の `always @(*)` が無いので、条件付き代入の行き先は必ずレジスタの D 入力になる。**ラッチ推論という厄介な問題がそもそも起きない**のがこの制限の効いているところで、「どの経路でも代入されなかった」は「D に Q を回す」＝保持と一意に決まる。

落とし方は、文を上から順に辿って「レジスタの各ビット → 次の値」の表を組み立てるだけ:

- `lhs <= rhs` は表を上書きする。同じビットに 2 回代入したら後が勝つ（Verilog のノンブロッキング代入と同じ）
- `if` は then 側と else 側を**表のコピーの上で別々に走らせて**から、`mux(cond, then側, else側)` で合流する。どちらかで触られていないビットは Q そのものを使う
- 両側が同じネットに行き着くビットには mux を作らない。分岐が触っていないビットはこれで素通しになる
- `case` は後ろの項目から積む。こうすると先に書いた項目の mux が外側に来て、Verilog の「上から順に最初に一致したものが勝つ」がそのまま出る。ラベルの一致判定には `==` の比較器を使う

右辺は常に Q（クロック前の値）を読む。`q <= a; r <= q;` の `q` が古い値になるのは、`refBits` が返すのが Q のネットだからで、特別な処理は要らない。

「既定値を先に置いて、条件が立った経路だけ上書きする」書き方（[examples/seqdet.v](examples/seqdet.v) の `found`）がそのまま通るのは、上書きが表の更新でしかないため。

### 到達不能ゲートの刈り取り

`schedule.js` は並べ切ったあとに、**出力ポートとレジスタの D から逆向きに辿って、そこに届かないゲートを `order` から外す**。外から見えるネットは線形メモリにスロットを持つものだけ（入力ポート・出力ポート・レジスタの Q）で、内部の組合せ配線は WASM の local に載るだけなので、届かないゲートは評価しなくても外から見た挙動は変わらない。

消えるのは 3 種類:

| 死ぬ理由 | 例 | 作った → 残った |
| --- | --- | --- |
| 幅の広い式を狭い左辺に代入した上位ビット | 8 ビットの `a - b` を 4 ビットに代入 | 50 → 24 |
| 条件付き代入を後の無条件代入が上書き | `if (c) q <= d;` の後に `q <= 4'h3;` | 6 → 2 |
| 使われなかった `$const0` / `$const1` | 定数リテラルを書かない回路 | 10 → 8 |

シフトレジスタ [examples/shift8.v](examples/shift8.v) が `gates=0` になるのは刈り取りのおかげで、`q <= {din, q[7:1]}` は本当に配線の付け替えだけで済んでいる（定数ゲート 2 個が刈られて何も残らない）。

**刈り取りは並べ切ってから最後にやる。** ループ検出が「全ゲートを並べ切れたか」で判定しているので、先に刈ると到達不能な場所にある組合せループを見逃す。順番に意味がある。

`compile()` が返す `stats.gates` は刈り取り後（＝生成コードに乗ったゲート数）で、消えたぶんは `stats.pruned` に出る。`vwc.js` も `gates=0(+2 刈り取り)` のように両方見せる。

### 非同期リセット

```verilog
always @(posedge clk or posedge rst)
  if (rst) q <= 8'h00;
  else if (en) q <= q + 1;
```

**どちらが非同期リセットかは、本体の先頭の `if` がどの信号を見ているかで決める。**Verilog もイベントリストの順番では決まらず、この形で書くのが決まりになっている。リセットが効いている条件は `if` の条件そのものを使うので、負論理も通る:

```verilog
always @(posedge clk or negedge rst_n)
  if (!rst_n) q <= 8'h00;
  else       q <= d;
```

エッジの向き自体は使わない。連続時間を持たないモデルなので、「リセット条件が真のあいだ Q が上書きされる」ことだけを表現する。

#### クロックを待たない、を cycle-based でどう表すか

非同期の意味は「クロックエッジを待たずに Q が変わる」。`eval` / `commit` に分かれたモデルでは**`eval` が Q スロットを書く**ことでこれを表す。レジスタ 1 個につき値が 2 つ出る:

| ネット | 中身 | 書く場所 |
| --- | --- | --- |
| `d` | `mux(rst, リセット値, 通常の次の値)` | `eval` が次状態スロットへ（`commit` が Q に移す） |
| `qAsync` | `mux(rst, リセット値, Q)` | `eval` が **Q スロットへ直接** |

`eval` は先頭で Q を local に読み終えているので、末尾で Q スロットに書いても今回の評価には影響しない（[codegen.js](src/codegen.js) が「読み込み → 評価 → 書き出し」の 3 段に分かれているのがここで効く）。その結果:

```js
sim.setInput('rst', 1).eval();   // → レジスタは 0 になる。step() は要らない
sim.setInput('rst', 0).eval();   // → 0 のまま (もう書き込まれている)
sim.setInput('d', 9).step();      // → 9
```

ただし**レジスタの下流にある組合せ出力は、もう 1 回 `eval()` を呼ぶまで追いつかない**。Q が書かれるのは `eval` の末尾で、その `eval` の中の組合せ論理は先頭で読んだ Q を使っているためである。これはクロックエッジのときと同じ事情で（`commit()` だけでは組合せ出力が古いまま残るので `step()` は末尾に `eval` を置いている）、`step()` / `run()` を使うぶんには表に出ない。`assign y = cnt;` のような下流を `eval()` 1 回で見たい場合は 2 回呼ぶ:

```js
sim.setInput('rst', 1).eval();   // レジスタは 0。ただし y はまだ古い
sim.eval();                     // ここで y も 0 になる
```

`eval` を常に 2 パスにすれば消せるが、非同期リセット付きの回路すべてで `eval` が 2 倍になるので採っていない。

`d` 側にもリセットを入れてあるので、リセット中に何クロック打っても Q はリセット値のまま。イベントが 1 つ（`always @(posedge clk)`）なら `if (rst)` はただの同期リセットで、`eval()` では変わらない。

リセット側に出てこないビットは「リセットしても保持」になる（`d` も `qAsync` も `mux(rst, Q, …)` になり、`qAsync` は畳み込みで `Q` そのものに落ちるので書き戻し自体が消える）。部分リセット（`b[1:0] <= 2'b01;`）も同じ仕組みで通る。

### モジュール階層

```verilog
module full_adder(input a, input b, input cin, output sum, output cout);
  wire s1, c1, c2;

  half_adder h0(a, b, s1, c1);                       // 順番で対応づけ
  half_adder h1(.a(s1), .b(cin), .s(sum), .c(c2));   // 名前で対応づけ

  assign cout = c1 | c2;
```

**展開しながら平坦化する。** `signals` は 1 個のフラットな Map で、キーはインスタンス名を前置した完全修飾名（`h0.s1`、`f0.h1.c`）。名前解決だけを現在のスコープで行うので、ビット展開から先の工程は階層をまったく知らないままで済む。

インスタンスごとの手順は 3 段:

1. 子の宣言だけ先に処理して、ポートのネットを作る
2. **親のスコープで**接続式を評価し、`buf` でポートに橋渡しする
3. 子の中身を子のスコープで展開する（入れ子はここで再帰）

2 を 3 より先にやるのが要点。子の `always` がクロックの同一性を見るとき、先に `buf` がつながっていないと親のクロックまでたどれない。ポートごとに `buf` を 1 個挟むのは GUI 側の[回路部品](#回路部品)と同じ理由で、**順序を気にしなくて済む**ため。

`--top` を省くと、どこからもインスタンス化されていない module を top に選ぶ。だから「部品を先に、top を後に」書いたファイルがそのまま通る。`--top` で部分木だけを切り出すこともできる。

スロット割り当て・スケジュール・駆動検査はいずれも「子のポートは top のポートではない」を見る。奥にあるレジスタは状態なのでスロットを持ち、完全修飾名で観測できる:

```js
sim.get('c0.cnt')   // 子インスタンス c0 の中のレジスタ
```

入れ子は 16 段まで。自己再帰と相互再帰はインスタンス化の経路を持って検出する（`p → q → p` のように出る）。

### parameter

```verilog
module counter #(parameter WIDTH = 8, parameter STEP = 1) (
  input clk, input rst, output [WIDTH-1:0] q
);
  localparam TOP = WIDTH - 1;
  reg [TOP:0] cnt;
  …
endmodule

counter #(.WIDTH(4)) c0(clk, rst, small);   // 名前指定
counter c1(clk, rst, big);                  // 既定のまま
counter #(4, 3) c2(clk, rst, by3);          // 順番指定
```

本体に書く形（`parameter WIDTH = 8;`）も通る。ヘッダと本体の宣言は 1 本の順序付きリストにまとめるので、後のものが前のものを参照できる（`parameter W1 = W + 1`）。`localparam` は値を導くだけの定数で、インスタンス化のときに差し替えられない。

#### ビット範囲は定数式で受ける

`parameter` 自体は値の入れ物にすぎず、`[WIDTH-1:0]` を書けることが本体:

- パーサは `[msb:lsb]` を数ではなく式として持つ（`parseExpr()` で受ける）
- elaborate の定数式評価器 `constExpr()` が、幅を持たない整数（BigInt）として計算する
- 範囲を数に落とすのは**パラメータの値が決まった後**。だからインスタンスごとのスコープで評価する順番が要る

インスタンスの手順は[階層](#モジュール階層)の 3 段の前に 1 段増えて 4 段になる:

1. **パラメータを決める。** 指定式は親のスコープで評価し（親のパラメータを渡せる）、既定値は子のスコープで評価する
2. 子の宣言（ここで `[WIDTH-1:0]` が数になる）
3. ポート接続（親のスコープで式を評価して `buf` で橋渡し）
4. 子の中身を展開

パラメータは完全修飾名（`c0.WIDTH`）で持つので、**同じ module を違うパラメータで何度でも展開できる**。[examples/counter_param.v](examples/counter_param.v) は同じ `counter` を 4 ビット / 8 ビット / 3 刻みで 3 個並べていて、`c0.cnt` は 4 ビット・`c1.cnt` は 8 ビットになる。

定数式で使えるのは `+ - << >> & | ^`、比較、`&& ||`、`!`、`? :`。**`~` は断る** — 幅が決まらないと意味が定まらないためで、その場でエラーにする。式の中でパラメータを使うこともでき（`assign p = W1;`）、そのときの幅はサイズ無しリテラルと同じ 32 ビット扱いになる（定数畳み込みと刈り取りで余りは消える）。

### 定数畳み込みと共通部分式除去

ゲートは入力だけで決まる純粋な関数なので、**作る前に**2 つ挟める。[elaborate.js](src/elaborate.js) の `newGate` がすべてのゲート生成の唯一の入口になっているので、ここに入れるだけで加算器・比較器・バレルシフタ・`case` の mux 木がまとめて恩恵を受ける。

- **定数畳み込み**: 入力が `$const0` / `$const1` なら、ゲートを作らず答えのネットを返す。`x & 0 = 0`、`x | 1 = 1`、`x ^ 1 = ~x`、`s ? 1 : 0 = s` など。同一入力（`x & x`）と `~~x`、`x | ~x` / `x & ~x` もここでたたむ
- **共通部分式除去**: `op` と入力の組をキーにした表を引いて、同じものがあれば出力ネットを使い回す。`and` / `or` / `xor` は可換なので入力を並べ替えてから引くため、`a & b` と `b & a` も共有される

効くのは主に**ゼロ拡張で入ってくる定数**である。`resize()` が幅を揃えるときに `$const0` を詰めるので、文脈依存幅とサイズ無しリテラルの 32 ビット化で入った定数が、そのままここで消える。

| 回路 | 前 | 後 |
| --- | --- | --- |
| [examples/counter8.v](examples/counter8.v) | 55 ゲート / 234 ネット / 897 バイト | **31 / 46 / 699** |
| [examples/seqdet.v](examples/seqdet.v) | 39 ゲート / 44 ネット / 664 バイト | **27 / 32 / 517** |
| [examples/shifter.v](examples/shifter.v) | 307 ゲート / 318 ネット / 3414 バイト | **96 / 108 / 1487** |
| [examples/window.v](examples/window.v) | 58 ゲート / 73 ネット / 631 バイト | **54 / 69 / 603** |

`shifter.v` の差が大きいのは `packed >> (8 - amt)` で、サイズ無しの `8` が 32 ビットなので素直に展開すると32 ビット減算器になるところを、定数側がたたまれて `4'd8` と書いた場合と同じ回路に落ちるため。

## 生成されるコード

`node tools/vwc.js examples/full_adder.v --wat` の実際の出力（抜粋）:

```wat
(module
  (memory (export "memory") 1)
  ;; input    a @ 0
  ;; output   sum @ 24
  (func $eval (export "eval")
    (local $n2_a i64 $n3_b i64 $n4_cin i64 $n5_sum i64 ...)
    ;; --- 状態の読み込み ---
    (local.set $n2_a (i64.load offset=0 (i32.const 0)))
    ;; --- 組合せ論理 (トポロジカル順) ---
    (local.set $n10__and6 (i64.and (local.get $n2_a) (local.get $n3_b)))
    (local.set $n8__xor2  (i64.xor (local.get $n2_a) (local.get $n3_b)))
    ...
    ;; --- 出力ポート ---
    (i64.store offset=24 (i32.const 0) (local.get $n5_sum)))
  (func $commit (export "commit") ...)
  (func $step (export "step") (call $eval) (call $commit) (call $eval))
  (func $run (export "run") (param $n i32) ...))
```

論理回路のコンパイル結果は**分岐のない直線コード**なので、使う命令は `i64.and` / `i64.or` / `i64.xor` / `local.get` / `local.set` / `i64.load` / `i64.store` だけ。`run` のループにだけ `block` / `loop` / `br_if` / `call` / `i32.sub` / `i32.eqz` が加わる。面倒なのは LEB128 エンコーダだけで、そこは 59 行に収まっている。

内部の組合せ配線は **local に置いてメモリを経由しない**。メモリに出るのは入力・出力・レジスタの状態だけ。

## ビットスライス（64 レーン同時実行）

1 ネットを 1 ビットではなく **i64 の 64 ビット**に割り当てている。64 ビットそれぞれが独立したテストベクタの「レーン」で、`step()` 1 回で **64 パターンを同時にシミュレート**できる。

これが JS ではなく WASM で出す理由。JS で 64 ビット整数演算をやると `BigInt` しかなく、`i64.and` に対して桁違いに遅い。

```js
// 素朴に使う: setInput() は全 64 レーンに同じ値をブロードキャストする
sim.setInput('a', 1).setInput('b', 0);
sim.step();
console.log(sim.get('sum'));            // → 1n

// 並列スイープ: レーンごとに違う入力を入れて 1 回の step で全部評価
for (let lane = 0; lane < 64; lane++) {
  sim.setInputLane('a', lane, lane & 1);
  sim.setInputLane('b', lane, (lane >> 1) & 1);
}
sim.step();
sim.getLanes('sum');                    // → 64 個の結果
```

実測（`node tools/bench.js`、32bit LFSR × 8 = 298 ゲート / 256 レジスタ）:

```text
WASM  : 29 ms / 200,000 クロック = 6877 kclk/s
        2049 M gate-eval/s (1 レーン換算)
        131 G gate-eval/s   (64 レーン同時換算)
参照JS : 2130 ms 相当 → WASM は約 73 倍速
```

## 3 つの実行単位

| 関数 | 意味 |
| --- | --- |
| `eval()` | 組合せ論理だけを評価する。レジスタは変えない |
| `commit()` | 次状態 → Q の一括転送（= クロックエッジ） |
| `step()` | `eval` → `commit` → `eval` |
| `run(n)` | `eval` → (`commit` → `eval`) × n |

この分離には理由が 2 つある。

**1. 純粋な組合せ回路では `eval()` が本来の操作**。入力を変えた直後に「クロックは打たずに出力だけ落ち着かせる」ことができる。

**2. `step()` 末尾の `eval` は必須**。これがないと、クロックエッジ直後の組合せ出力が「エッジ前の状態から計算された値」のまま残る。`run(n)` はこの余分な `eval` を畳んで `n+1` 回の eval で `n` クロックを回す。

### 次状態スロットはレジスタごとに持つ

次状態のスロットは **D ネットごとではなくレジスタごとに専用で確保**している。これを D ネットで共有すると `a <= b; b <= a;` が壊れる。

`a` の D ネットは `b` の Q ネットそのものなので、スロットを共有すると `commit` が「a に旧 b を書く → b に *新しくなった* a を書く」という逐次代入になってしまう。レジスタごとに専用スロットを持たせると、この種のエイリアシングが構造的に起こり得なくなる。

## API

```js
import { compile } from './src/compile.js';
import { WasmSimulator } from './src/sim.js';

const compiled = compile(verilogSource);   // { bytes, wat, netlist, layout, stats, warnings }
const sim = await WasmSimulator.create(compiled);

sim.setInput('d', 0b1010);   // 入力ポート（reg も書けるので初期値のシードに使える）
sim.eval();                  // 組合せ論理のみ評価（クロックは打たない）
sim.step();                  // 1 クロック
sim.run(1000);               // 1000 クロック（ループは WASM 側にある）
sim.get('q');                // → BigInt
sim.getLanes('q');           // → 64 レーン分の BigInt[]
sim.reset();                 // 全状態をゼロクリア
sim.snapshot();              // 観測可能な全信号
```

`RefSimulator`（[src/interp.js](src/interp.js)）は同じ API を持つ JS 参照実装。

中核は **WASM バックエンド vs JS 参照実装の差分テスト**。ランダムに生成した Verilog 25 回路 × ランダム入力 12 ベクタで、両者の出力が完全一致することを確認する。生成器は `+` `-`・比較 6 種・`<<` `>>`・`&&` `||` `!`・リダクション 6 種・`if` / `case`・非同期リセット・子モジュールのインスタンス化を混ぜる。25 回路の中に各構文が現れること自体もテストしている。

**演算子は差分テストの枠の外**にある。加算器も比較器も mux 木もビットに展開した時点でふつうのゲートの塊になるので、WASM と参照実装は同じネットリストを見ていて、間違っていれば揃って間違う。ここは **JS で素直に書いたモデルと直接**比べる:

| スイート | 突き合わせる範囲 |
| --- | --- |
| `加算・減算` / `比較器` | 4 ビット × 4 ビットの全 256 通り。6 種の比較演算子、桁上げ、切り詰め、優先順位 |
| `文脈依存幅` | 文脈が配られる側と配られない側を並べ、同じ `a - b` が代入先の幅で 14 / 30 / 254 / 65534 になること |
| `刈り取り` | 消えるべきものが消え、観測できる値が変わらないこと。到達不能な組合せループを見逃さないこと |
| `リダクション` | 幅 4 / 幅 3 の全通り × 14 出力。奇数幅のパリティ、`~^` と `^~` の一致、ゲート数 n-1 |
| `論理演算子` | 全 256 通り。`!` と `~` の違い、`&&` `\|\|` `\|` `==` 単項の優先順位 |
| `シフト` | 値 16 × 量 8 × 幅を超える量 16。定数シフトがゲートを増やさないこと、バレルシフタの段数 |
| `if / case` | 11 種類の分岐（保持・`else if`・複数ラベル・`default`・重複ラベル・入れ子・部分代入）を 10 サイクル |
| `FSM` / `ALU` | [seqdet.v](examples/seqdet.v) に 20 ビット列、[alu4.v](examples/alu4.v) の 8 演算 × 5 組 |
| `parameter` | [counter_param.v](examples/counter_param.v) の 3 インスタンスが別々に展開されること、定数式の範囲 |
| `モジュール階層` | [adder2.v](examples/adder2.v)（2 段の入れ子）の全 4×4×2 通り、完全修飾名、`--top` |
| `非同期リセット` | `eval()` だけで Q が変わること、負論理・非ゼロ値・部分リセット、同期リセットとの違い |

ほかに全加算器の真理値表、DFF のタイミング、LFSR の周期 255、レジスタのスワップと 3 段ローテーション、`eval` / `commit` の分離、64 レーンの独立性、45 種類のコンパイルエラー。

`GUI 回路グラフ` はエディタのサンプル回路（[src/samples.js](src/samples.js)）を Verilog に変換して突き合わせる。組合せ回路は真理値表、メモリ入りの回路は入力を変えながらクロックを打った値の列で確認する。未配線の部品が下流ごと除外されること、フィードバック配線が組合せループとして弾かれる一方で**メモリを挟んだ帰還は通る**ことも見ている。

## ブラウザデモ

`web/` の 2 ページは ES モジュールを import するため `file://` では開けない（CORS でブロックされる）。

```bash
node tools/serve.js   # → http://localhost:8080/web/
```

**[web/index.html](web/index.html) — テキスト版。** Verilog を書いてコンパイルすると、生成された WAT・信号の波形・入力コントロールが出る。「1M クロック計測」ボタンでスループットも測れる。

**[web/editor.html](web/editor.html) — GUI 回路エディタ。** 1 ビットの入出力・論理ゲート・定数（0 / 1）・1 ビットのメモリ（DFF）・**保存した回路そのもの**を置いて配線する。操作は 4 つだけ。

- **左サイドのパレット**でボタンを押すと置かれる。ドラッグで移動、選択して `Del` で削除
- 端子をクリック → もう一方の端子をクリックで配線。線をクリックで切断
- 入力と定数の箱をクリックで 0/1 反転
- 部品を右クリックすると、その場で **上段に名前・下段に幅**の欄が出る（`F2` は名前だけ）

編集の操作は次の3つ。

- **範囲選択**：背景をドラッグすると矩形に触れた部品が選ばれる。`Shift` + クリックで足し引き、`Ctrl+A` で全部。選択した部品はまとめて動かせる
- **コピーと貼り付け**：`Ctrl+C` / `Ctrl+X` / `Ctrl+V`。**選択の中で閉じている配線ごと**複製する。端子名がぶつかるときは `sum_2` のように後ろに番号を足す。別のタブで開いた回路にも貼れる
- **元に戻す / やり直し**：`Ctrl+Z` / `Ctrl+Shift+Z`（`Ctrl+Y` も可）。60 手ぶん。入力の 0/1 は編集ではないので手順には積まない

表示の操作は次の3つ。`Ctrl` + ホイールはカーソルの下にある点を固定して拡大縮小する（1/4 〜 8 倍）。

- `Ctrl` + ホイールで拡大縮小、何もない所をドラッグでスクロール、「表示リセット」で元に戻る
- キャンバスと右パネルの境界をつまむと幅が変わる。Verilog と真理値表の境界をつまむと高さの配分が変わる
- 回路と波形パネルの境界をつまむと波形の高さが変わる

部品は 18 個あるので、キャンバスの左に縦のパレットとして 2 列に畳んで並べてある（`入出力` / `ゲート` / `メモリ` / `幅` / `算術` の見出しつき）。上のツールバーは 1 段ずつの 2 本で、回路の操作（上段）と回路そのものの出し入れ（下段）に分かれている。

配線を変えるたびに Verilog を生成 → WASM にコンパイル → `eval()` まで走る。配線の色がそのままビットの値（緑 = 1）で、生成された Verilog も横に出る。

### 保存と読み込み

- **自動保存**。編集中の回路は変更のたびに localStorage に入るので、閉じても次に開いたとき続きから始まる
- **名前を付けて保存**。名前を入れて「保存」を押すと、リストの「保存した回路」に並ぶ。同じ名前なら上書き。「保存を削除」で消える
- **共有リンク**。「リンクをコピー」で回路そのものを URL に埋め込む（`#c=…`）。サーバに何も置かないので、リンクを送るだけで相手が同じ回路を開ける。AND ゲートで 150 文字ほど、バレルシフタで 1.8 KB ほど
- **`.json` で書き出す / 読み込む**。「.json を保存」でファイルに落とし、「.json を読み込む」で戻す。中身は共有リンクと同じ保存形式なので、リンクとファイルを相互に行き来できる。大きい回路は URL に載せると長くなるので、そういうときはファイルのほうが向いている

読み込みの優先順位は、共有リンク（`#c=…`）→ サンプル名の一部（`?c=半加算器`）→ 自動保存 → 先頭のサンプル。

保存形式は**サンプルとまったく同じ圧縮形式**にしてある。おかげで「サンプル」と「保存した回路」を 1 つのリストにまとめて、同じ経路で読み込める。

```js
{ nodes: [[1, 'in', 40, 90, 1, 'd0'], …],   // [id, 種類, x, y, 値, 端子名]
  wires: [[1, 0, 3, 0], …] }                // [出力ノード, 0, 入力ノード, 端子]
```

書き出す `.json` は上の形に回路名（`name`）を足して 1 行ずつ並べただけ。`name` は `expandCircuit()` が見ない追加フィールドなので、共有リンクの中身をそのままファイルにしても読める（逆も同じ）。知らないフィールドは無視される。

読み込むデータは URL やファイル経由で他人から来ることもあるので、`expandCircuit()` で検査してから受け取る。知らない部品・id の重複・座標が数値でないものは理由を付けて弾き、**筋の通らない配線（繋ぎ先が無い・端子番号が範囲外・同じ入力端子への 2 本目）は黙って捨てる**。配線 1 本のために回路全体が開けなくなるほうが困るので、ここは弾かずに落とす。

サンプル 16 個は [src/samples.js](src/samples.js) にある。AND / 半加算器 / NAND 4 個で XOR / 多数決 / 組合せループ（エラーになる例）/ 1 ビットメモリ 2 種、バスもの（ビット演算・メモリのトグル・加算器と比較・部分選択・多入力の連接・絶対差・NOR/XNOR）、4 ビットバレルシフタ、全加算器（半加算器を部品にして 2 個）。

### 幅 (バス)

**入力・定数・メモリはビット幅を持てる。** **部品を右クリックすると下段に幅の欄が出る**ので、そこに入れる（1〜32）。まとめて変えたいときはツールバーの「幅」でも同じことができる。ゲートと出力は幅を持たず、**繋いだ先から伝わる**ので、置き方は 1 ビットのときと変わらない。

幅を自分で持つのを入力・定数・メモリに限ったのが要点。メモリが自分で持つ必要があるのは、「メモリ → NOT → メモリ」のような帰還があると伝播だけでは幅を決める手がかりが無くなるためである（循環して決まらない）。

```verilog
// 4 ビットの入力 2 本を AND した回路の出力。宣言だけが変わり、式は 1 ビットのときと同じ
module sketch(
  input  [3:0] a,
  input  [3:0] b,
  output [3:0] n3,
  output [3:0] y0
);
  assign n3 = a & b;
  assign y0 = n3;
endmodule
```

コンパイラ側は元からベクタが通るので、**この機能で追加した Verilog の生成は「宣言に `[W-1:0]` を付ける」だけ**。ビットごとの演算はそのまま任意幅で正しい。

#### 幅が合わないときは未配線と同じ扱いにする

4 ビットと 1 ビットを AND のような回路は、そのゲートと**下流ごと回路から外して**理由を出す。黙って切り詰めたり広げたりすると、画面で見えている線と生成される回路が食い違うため。未配線の部品を外すのと同じ仕組みなので、外れた部品は同じように薄く表示される。

#### 値の見せ方と入力

**1 ビットでないバスは、それを運ぶ端子のそばに幅を出す。** 幅 1 には出さない — 出すと全部の端子に `1` が並んで、かえってバスが見つけにくくなるため。幅を持つ部品（入力・定数・メモリ・ビット取り出し）だけでなく、**伝播で決まった幅も同じように出る**ので、どこからどこまでがバスなのかを回路図だけで追える。

数字だけを出して `8b` や `[7:0]` のような単位を付けないのは、**画面の密度を上げないため**。意味は置き場所に持たせてある = 端子のすぐ上に浮いている数字は幅、箱の中の数字は値。角括弧を使わないのも、ビット取り出しの箱に出る `[5:2]`（**どのビットか**）と読み違えないためである。

幅を運ぶのは出力端子なので、数字は出力端子に付く。**出力ポートだけは出力端子を持たない**ので、幅が入ってくる左の端子に付ける。回路部品（block）は端子ごとに幅が違うため、端子ごとに出す。

幅 1 は今までどおり 0/1 で、**幅 2 以上は 16 進**（部品・真理値表・波形で揃えている）。入力の値は幅 1 ならクリックで反転、幅 2 以上はクリックで小さな入力箱が開く（16 進で何度もクリックさせるのは現実的でないため）。名前を変える箱と同じ仕組みを使っている。

波形は幅 1 なら階段、幅 2 以上は**列ごとに値の箱**を並べる。階段では 4 ビットを表せないためで、行の名前も `a[3:0]` と幅つきで出る。

真理値表は 64 レーンの制約がそのまま効く。1 軸が 1 ビットではなくなったので**幅の合計**で判定し、6 ビットを超えたら今までどおり理由を出して表を出さない（4 ビット入力が 2 本なら 8 ビットなので出ない）。

#### 幅は部品のそばで打つ

部品を右クリックすると、その場に欄が出る。

```text
      ┌──────────────────┐
      │        a         │  ← 上段: 名前 (入出力・メモリだけ)
      └──────────────────┘
      ┌──────────────────┐
      │ 幅  [-]  8  [+]  │  ← 下段: 幅 (連接では「本数」)
      └──────────────────┘
```

出るのは持っているものだけ。入力とメモリは 2 段、定数・ビット取り出し・連接は名前を持たないので下段だけ、ゲートは両方持たないので理由を出して何も出さない。`Enter` で確定して 2 段まとめて閉じ、`Escape` で取り消し、欄の外を押しても確定して閉じる。下段の枠を端子の幅の数字と同じ色にしてあるのは、**値を打つ箱と間違えないため**（値の箱は左クリックで、部品の本体にぴったり重なって出る）。

**`-` と `+` は押した時点で 1 ずつ効く**（`↑` / `↓` キーでも同じ）。上限（32）と下限（1、連接は 2）に届いたボタンは押せなくなる。

ツールバーの「幅」も残してある。**複数選択にまとめて効く**のはこちらだけで、右クリックは 1 個ずつ。どちらも同じ `applyWidth()` を通るので、端子が減ったときに配線を落とす処理も共通である。

#### 幅を混ぜる / 算術の部品

バスを「まとめて演算する」だけでは足りないので、幅を跨ぐ部品と算術の部品を用意した。どれも生成される Verilog は 1 行で、コンパイラ側は元から全部通る。

| 部品 | 端子 | 生成される式 | 出力の幅 |
| --- | --- | --- | --- |
| ビット取り出し | 1 → 1 | `y = a[2]` / `y = a[5:2]` | 取り出すビット数 |
| 連接 | **n** → 1 | `y = {a, b, c, d}` | 入力の幅の**合計** |
| 加算 / 減算 | 2 → 1 | `y = a + b` / `a - b` | 入力と同じ（桁上げは捨てる） |
| 一致 / 小なり | 2 → 1 | `y = a == b` / `a < b` | 1 |
| 選択 | 3 → 1 | `y = s ? a : b` | データ側と同じ |

**ビット取り出しは 2 つの数を持つ。** 「いちばん下のビット番号」は値の枠に、「取り出すビット数」は幅の枠に入れる。つまり**幅を付けると部分選択になる**（幅 1 なら `a[2]`、幅 4 で下端 2 なら `a[5:2]`）。番号は箱をクリックして 10 進で、ビット数は「幅」の欄で決める。

番号のほうは幅ではなく添字なので、値を幅で丸める処理から外してある（幅 1 扱いで 0/1 に潰れてしまう）。はみ出す範囲を指したときは、幅が合わないときと同じく下流ごと外して理由を出す。

**連接は入力の本数を設定する。** 同じ「幅」の欄を使うが、連接だけは中身が本数になる（`w` の枠を幅としてではなく本数として読む）。1 ビットの線 8 本を 1 本のバスにしたいとき、2 入力固定だと連接を 7 個つなぐことになるので、本数そのものを持たせた。各入力の幅はこれまでどおり配線から決まり、出力はその合計。

```text
本数 2 → assign y = {a, b};           上の端子が上位ビット
本数 4 → assign y = {a, b, c, d};
```

本数の下限は 2（1 本の連接は連接ではない）で、上限は幅と同じ 32。**本数を書いていない保存データは 2 入力**として読まれるので、これまでの回路はそのまま開ける。本数を減らして端子が消えたときは、その先に繋がっていた配線も落とす。埋まっていない端子が 1 本でもあると幅が決まらないので、未配線の部品と同じく下流ごと回路から外れる。

幅の規則は部品ごとに違うので、伝播の規則を分けてある:

| 規則 | 意味 | 部品 |
| --- | --- | --- |
| `same` | 入力は全部同じ幅、出力もその幅 | ゲート・出力・中継 |
| （自分で持つ） | 宣言した幅がそのまま出力の幅 | 入力・定数・メモリ・ビット取り出し |
| `sum` | 出力は入力の幅の合計 | 連接 |
| `cmp` | 入力は同じ幅、出力は 1 ビット | 一致・小なり |
| `mux` | 1 本目は 1 ビット、残りは同じ幅 | 選択 |

規則から外れたもの（取り出す範囲がバスの幅の外、比較の両辺の幅が違う、選択信号が 1 ビットでない、連接で 32 ビットを超える）は、幅が合わないときと同じく**下流ごと外して**理由を出す。

端子が 3 本以上ある部品（選択・多入力の連接）のために、箱の高さと端子の間隔は端子の数で決まるようにした。**2 本までは今までと同じ位置**にしてあるので、既存の回路の見た目は変わらない。

#### 保存形式は後ろ向き互換

幅は保存形式の 8 番目の枠に入れ、**1 のときは書かない**。だから幅を知らない頃の保存データや共有リンクはそのまま開けて、幅 1 として読まれる。範囲外の幅や幅に収まらない値は読み込み時に丸める。

連接の入力の本数も同じ 8 番目の枠を使う。読むときの下限が 2 なので、**枠が空でも範囲外でも 2 入力**に落ちる = これまでの連接と同じになる。枠を 1 個増やさずに済むのはこの下限のおかげで、保存形式は幅を入れたときから変わっていない。

### 端子の名前

入力・出力・メモリには名前を付けられる。付けた名前がそのまま Verilog のポート名になり、回路図・真理値表・状態遷移表の見出しもそれで出る。自動名の `a` / `y0` / `n7` で 6 入力の回路を読むのは辛いので、バレルシフタは `d0..d3` / `s0,s1`、メモリのサンプルは `d` / `en` / `mem` / `q` と名前を付けてある。

名前は Verilog の識別子として妥当か・予約語でないか・他の端子と重複しないかを `checkName()`（[src/schematic.js](src/schematic.js)）で検査して、駄目なら理由を出して弾く。空にすると自動名に戻る。自動名は「空いている名前」を取るので、手で `a` を付けた入力があれば次の自動名は `b` になる。

### 定数

`0` / `1` に固定された値。ポートではなく `assign n5 = 1'b0;` というリテラルになる。バレルシフタで「シフトして空いた桁」に入れているのがこれで、定数がないと桁を捨てられず巡回シフトしか作れない。

### 回路部品

**保存した回路を、別の回路の部品として置ける。** 半加算器を保存しておけば、それを 2 個並べて全加算器が組める（サンプルの「全加算器 (半加算器を部品にして 2 個)」がそれ）。中身の入力ノード・出力ノードがそのまま部品の端子になり、**端子名も中身の名前がそのまま出る**ので、名前を付けておくと部品が読みやすくなる。

`保存 → 部品 [回路を選ぶ] → 置く` の順。中にメモリがあっても構わない（クロックは全体で 1 本の共有なので、部品の中の DFF も同じクロックで動く）。

**中身は参照ではなく、置いた時点でコピーして埋め込む。** そのおかげで保存も共有リンクも単体で完結し、相手の localStorage に元の回路が無くても開ける。元を直したときは「部品」の「更新」で埋め込みを最新に差し替える（端子が増減した場合は筋の通らなくなった配線だけ落ちる）。

#### 中を開いて編集する

部品をダブルクリック（または選んで「部品」の「中へ」）すると、**中身がそのまま canvas に開く**。編集して「確定して戻る」を押すと親の部品に書き戻り、「取消して戻る」なら捨てて戻る。入れ子も辿れて、いまどこにいるかはパンくず（`fa › 半加算器`）に出る。

実装は「親をスタックに積んで、中身を普通の回路として開く」だけ。各フレームに親の回路・書き戻す先のノード id・名前欄とリストの選択・**親の Undo 履歴**を預けておく。書き戻しは「中身の編集」1 手として積むので、Undo 1 回で編集前に戻せる。

- **書き戻すときは保存された回路への `ref` を切る**（切らないと「更新」がこの編集を上書きしてしまう）。切り離したことはメッセージで伝える
- **自動保存は常に一番外側を書く。** 部品の中にいるあいだも、いまの中身を親に畳み込んだ回路を保存する
- **入出力が無い中身は確定させない。** 部品になれないので、その場に留まって直せるようにする

中にいるあいだは「回路そのもの」を相手にする操作（保存・共有リンク・`.json`・回路の切り替え）を止める。中に別の部品を置くのは階層として筋が通るので、そちらは触らない。

コンパイラにも[モジュール階層](#モジュール階層)はあるが、**GUI の部品はそれを使わず「中身を親に取り込む」平坦化で実現している**。生成される Verilog は 1 個の module のままなので、部品を使った回路でも出力される Verilog は素直に読める。

```verilog
module sketch(input a, input b, input cin, output sum, output cout, …);
  assign u10_a = a;                  // 部品の端子は中継の assign になる
  assign u10_b = b;
  assign u10_n3 = u10_a ^ u10_b;     // 中身の信号には u<部品の id>_ が付く
  assign u10_sum = u10_n3;
  assign u11_a = u10_sum;            // 1 段目の sum が 2 段目の a へ
  …
```

端子ごとに中継（`assign x = y;`）を 1 個挟むのは、**順序を気にしなくて済むから**。部品同士を相互に繋いだ場合もただのグラフの循環になるので、組合せループとして `schedule.js` がそのまま見つけてくれる。入れ子は 8 段まで、広げた後の部品数は 4000 まで。

### 1 ビットのメモリ

`DFF` を置くと生成される Verilog に `input clk` と `always @(posedge clk)` が生える。クロックは全体で 1 本の共有で、「▷ 1 クロック」ボタン（または `Space`）が `sim.step()`（`eval` → `commit` → `eval`）を 1 回呼ぶ。「メモリをクリア」は `sim.reset()`。

メモリの Q を反転して自分の D に戻せば 1 ビットのトグルになる。**組合せループとしては弾かれない**のがポイントで、フリップフロップを挟んだ帰還は `schedule.js` から見て Q が始点・D が終点の別ネットなので順序が付く。

```verilog
module sketch(input clk, output reg n1, output n2, output y0);
  assign n2 = ~n1;      // Q を反転
  assign y0 = n1;
  always @(posedge clk)
    n1 <= n2;           // それを D に戻す → クロックごとに 0 → 1 → 0 …
endmodule
```

### 波形

下のパネルが波形。**1 列 = クロック 1 回**で、`▷ n クロック` でまとめて打てる。メモリのある回路では入力をいじっても列は増えず今の列が書き換わる（同じサイクル内の出来事なので）。クロックのない組合せ回路では列の意味が無くなるので、代わりに**入力を変えるたびに 1 列進める**（実験のログになる）。

既定では入力・メモリ・出力だけを出す。ゲートの数だけ行が増えると読めないので、内部の配線は「内部の配線も出す」で任意に足す。値が分からない区間（未配線の下流）は破線で中央に引く。

**波形をクリックするとその列にカーソルが付き、全信号の値が名前の右に出る。** 階段の高さを目で追わずに「このサイクルで何が起きたか」を読める。矢印キー（← →）で 1 列ずつ送れて、同じ列をもう一度クリックするか Escape で外れる。値の列は常に場所を取ってあり（カーソルの有無で波形が横にずれないように）、カーソルを置いているあいだは右端に自動スクロールしない。上限の 256 列を超えて古い列が落ちるときはカーソルを末尾に寄せる。

各波形の `<path>` には `data-sig` / `data-bits`（`"011110"` のような文字列）を付けてある。カーソル位置の値にも `data-sig` / `data-val` を付けてある。どちらもヘッドレスブラウザから中身を 1 ビットずつ検証するためで、目で見るためのものではない。

### 表もビットスライスで作っている

右下の表は**ビットスライスの 64 レーンをそのまま使う**。組合せ回路なら入力 n ビットの全 2ⁿ パターンをレーンに並べて `eval()` を 1 回呼ぶだけで全行が埋まる。

メモリがある回路では「入力 + 現在の Q」を軸にした状態遷移表になる。こちらも 1 回で済むが順番が要る ―― 出力は `commit` の前、次状態の Q は `commit` の後に読む。合計 6 ビット（= 64 レーン）まで。今の入力とメモリの値に当たる行には印が付く。

ゲートの出力は内部 wire ではなく **output ポートとして宣言している**。内部の組合せ配線は WASM の local に置かれてメモリに出ないので、そのままでは線の値を読めない。output にすれば全ての配線が観測できる。

## 次にやること

- エディタ: 波形の列をドラッグして範囲を選び、その区間だけ表を作る
- エディタ: 部品のライブラリを .json でまとめて出し入れする（いまは回路 1 個ずつ）
- コンパイラ: 複数クロック。いまは `step()` がエッジそのものなので、実行モデルの拡張から必要になる
